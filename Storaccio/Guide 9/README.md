# Guide 9 - ESP32 FreeRTOS Interrupt + Semaphore Example

## 1. What this program does

This project runs on an ESP32 using ESP-IDF + FreeRTOS.

It demonstrates a classic real-time pattern:

- A GPIO interrupt (button press) triggers an ISR.
- The ISR releases a binary semaphore.
- A high-priority task wakes up, toggles an LED, and prints elapsed time since the previous event.
- A low-priority telemetry task prints a heartbeat every 5 seconds.

In short: this is a clean example of interrupt-to-task communication in a real-time system.

## 2. Hardware used

- Board: ESP32 (target detected as `esp32` in `build/project_description.json`)
- LED pin: GPIO2 (`LED_PIN`)
- Button pin: GPIO0 (`BUTTON_PIN`)
- Serial monitor baud: 115200 (`monitor_baud`)
- Configured serial port (VS Code setting): `/dev/ttyUSB0`

## 3. Core concepts explained

### ISR (Interrupt Service Routine)

The function `isr_boton()` runs when the button pin detects a falling edge.

Important ISR rules (followed in this code):

- Do not block.
- Do not use delays.
- Keep it short and fast.
- Use ISR-safe APIs only (`xSemaphoreGiveFromISR`).

### Binary semaphore

A binary semaphore is used as a synchronization signal:

- ISR gives the semaphore.
- Processing task takes the semaphore.

This is safer and cleaner than doing heavy work inside the ISR.

### Task priorities

Two tasks are created on Core 1:

- `tarea_procesamiento`: priority 3 (high)
- `tarea_telemetria`: priority 1 (low)

When the button event arrives, the high-priority task gets CPU first.

### Blocking and CPU usage

- `xSemaphoreTake(..., portMAX_DELAY)` blocks the processing task until an event arrives.
- `vTaskDelay(pdMS_TO_TICKS(5000))` blocks telemetry for 5 seconds, freeing CPU time.

This is fundamental in RTOS design: block tasks instead of busy-waiting.

## 4. Source code walkthrough

Main logic lives in `main/main.c`:

1. Configure LED GPIO as output.
2. Configure button GPIO as input with pull-up and falling-edge interrupt.
3. Install GPIO ISR service and attach `isr_boton`.
4. Create binary semaphore.
5. Create processing and telemetry tasks.

Expected runtime behavior:

- Every 5 seconds: `Sistema Operativo Saludable`
- On each button press:
  - LED toggles ON/OFF
  - Log prints: `Evento! Tiempo desde ultimo evento: X ms`

## 7. How to build, flash, and monitor (step by step)

## 7.1 Open an ESP-IDF environment

Use an ESP-IDF terminal (or source export script manually) so `idf.py` and toolchains are available.

Example (if needed on Linux):

```bash
source "$HOME/.espressif/v6.0.1/esp-idf/export.sh"
```

Then go to project root:

```bash
cd "/home/masterxdual/Escritorio/The Future/IUA/Time Real Systems/Real-Time-Systems/Storaccio/Guide 9"
```

## 7.2 Build

```bash
idf.py build
```

What this command does:

- Configures CMake if needed.
- Compiles all required ESP-IDF components and your app code.
- Links everything into `build/Guide.elf`.
- Generates `build/Guide.bin` to be flashed.

## 7.3 Flash

```bash
idf.py -p /dev/ttyUSB0 flash
```

What this command does:

- Opens serial port `/dev/ttyUSB0`.
- Resets the board into bootloader mode.
- Writes binaries into flash memory.

From your generated flash args, the write layout is:

- `0x1000` -> `bootloader/bootloader.bin`
- `0x8000` -> `partition_table/partition-table.bin`
- `0x10000` -> `Guide.bin`

## 7.4 Monitor

```bash
idf.py -p /dev/ttyUSB0 monitor
```

What this command does:

- Opens serial monitor at configured baud (`115200`).
- Shows boot logs and `ESP_LOGI` output in real time.

To exit monitor: press `Ctrl+]`.

## 7.5 One-command flow (optional)

You can combine flashing and monitoring:

```bash
idf.py -p /dev/ttyUSB0 flash monitor
```

## 8. Useful first learning goals

If you are new to RTOS/ESP32, use this project to practice:

1. Understanding the difference between ISR context and task context.
2. Why semaphores are used for ISR-to-task signaling.
3. How task priority affects execution order.
4. How blocking APIs (`xSemaphoreTake`, `vTaskDelay`) avoid wasting CPU.
5. How build artifacts (`.elf`, `.bin`, map) map to firmware deployment.

## 9. Notes

- The `build/` directory is generated and can be recreated.
- If board, port, or SDK version changes, update `.vscode/settings.json` and/or run configuration commands again.
- If GPIO0 is used as boot strap on your board, button wiring must be done carefully.

## 10. Software Usage

To start using ESP-IDF on ESP32, you need the following software:

- Toolchain to compile code for ESP32.
- Build tools - CMake and Ninja to build a full Application for ESP32.
- ESP-IDF that essentially contains API (software libraries and source code) for ESP32 and scripts to operate the Toolchain.
